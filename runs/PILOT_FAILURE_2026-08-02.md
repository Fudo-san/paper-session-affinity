# パイロット失敗の記録 2026-08-02

利用上限に当たって停止した。その過程で**測定の妥当性に関わる欠陥が3つ**見つかった。
いずれも「記録上は成功した run」に見えてしまう種類のもので、気付かなければ
本実験のデータを汚染していた。

## 起きたこと

| 時刻(JST) | 出来事 |
|---|---|
| 03:39:16 | 開始。1本目が cost 0 で失敗（検知されず） |
| 03:42–04:04 | 10ラン成功。実課金 $9.90 |
| 〜04:05 | 利用上限に到達 |
| 04:05–04:29 | 残り25ランを各3秒で空回し。**何もしないまま12分の cooldown を2回眠った** |

36ラン中、実際にモデルを呼べたのは10ラン。上限到達後の25分はまるごと無駄。

## 欠陥1: 空振りを成功として記録していた

`development_phase` は provider が枯渇しても例外を投げずに戻る。その結果
cost=0・トークン0・wall 3秒の run が `status=completed` として台帳に載り、
ドライバは残りの予定を淡々と消化した。

**対処**: モデル呼び出しが1回も記録されなかった run を `NoModelCallError` として
即座に中断する。台帳には `status=aborted` と原因を残す。

検証済み。実際に走らせると1本目で止まり、理由まで出る:

```
[FAIL] T-17101: No available agent backend:
       claude: blocked by usage limit until 2026-08-02T01:30:39Z
[ABORT] 空振りを検出したので中断する
```

## 欠陥2: 実験用スプリントが対象リポジトリの実在スプリントと衝突していた

ドライバは plan を `sprints/sprint_1/plan.json` へ置いていたが、square-media には
**実在する sprint_1** があり、worktree には最初から
`sprints/sprint_1/sprint_done.json` と過去の `results/` が入っている。

`fwcore/sprint.py:83` の `is_sprint_done()` は完了フラグを見て SKIP する。
`development_phase` を直接呼ぶ経路では発火しなかったが、完了済みスプリントの
残骸の上で毎回実行していたこと自体が不健全である。

**対処**: 実験専用の `sprint_exp` を使い、実行前にディレクトリごと作り直す。

## 欠陥3: provider フォールバックがアームCを黙って無効化しうる

`ProviderScheduler` は primary が落ちると既定で **codex へ落ちる**
（`mk2_config` の `providers.fallback` 既定値が `"codex"`）。

実験中にこれが起きると:

- `CodexCliBackend.supports_resume = False` なので、
  **アームC（レーン継続）が黙ってアームB相当に成り下がる**
- モデルが変わるためコストが比較不能になる

そして**記録上は成功した run に見える**。これが本実験中に一度でも起きていれば、
そのデータは無効だが、それと気付く手段がなかった。

**対処**: 実験中は `provider_scheduler.fallback = None` にする。落ちたら
落ちたまま中断させ、フォールバックで取り繕わせない。

## 欠陥4（前回からの持ち越し）: A5 汚染を相殺で済ませていた

resume が作ったキャッシュを後続の新規初期化が踏む経路（A5）に対し、
12分の cooldown と ABBA で**相殺**していたが、無効化していなかった。
12分は M2 の実測 10.2分からの推定であって上限の保証ではない。

**対処**: M1 で使った手法を本番へ入れる。`runner._invoke_agent` で、
run ごとに一意な文字列をプロンプト先頭へ付ける。
TTL が何分でも run をまたぐプレフィックス共有が原理的に成立しない。
run 内では同一値なので、アームCの resume（session_id で継続）は影響を受けない。

## 再開できるようにした

上限は今後も来る。当たるたびに全部やり直す運用は費用が持たない。
`--skip-done` で、有効な結果（cost>0）がある run を飛ばして続きから流せる。
cost=0 の空振りは「済み」と見なさず、やり直す。
