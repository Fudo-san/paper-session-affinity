## 決定1: 仕様は6件すべてを回す

`benchmarks/specs.json` の6仕様すべてを本実験の対象とする。系列で絞らない。

| 系列 | spec_id | 形状 |
|---|---|---|
| 1（nightly カード / `d4449a0`） | `n_db_chain` / `w_two_files` / `m_mixed` | N / W / M |
| 2（sprint_17-1 / `3be3676`） | `s17_n_db_chain` / `s17_w_two_files` / `s17_m_mixed` | N / W / M |

### 理由

- `rqs_hypotheses.md` の「3〜5仕様」は設計時の**想定**であり、仮説・指標・判定基準では
  ない。仕様数を増やしても、事前に固定してある限り都合のよい結果を選ぶ余地は生じない。
- 系列を1つに絞ると、効果（または効果の不在）がその仕様群に固有でないことを示せない。
  形状 N/W/M を2系列で反復することが、本実験の外的妥当性の主たる担保である。
- 系列2は別リポジトリ状態・別ファイル群・別ベースコミットであり、系列1と独立している。

### 引き受ける不利

- 費用と所要時間が倍になる。
- 多重性が増える。これは `rqs_hypotheses.md` の gatekeeping 構造
  （RQ1 を主要、RQ2/RQ3 を co-gate）で既に扱われており、本決定で変更しない。

## 決定2: パイロットは6仕様 × 3反復

パイロットの目的は `rqs_hypotheses.md` の規定どおり **反復数 N の決定のみ**である。
仮説・アーム・指標・閾値・除外規則をパイロット結果で変更しない。

- 反復 3、cooldown 12分、`--label pilot`
- 出力は `runs/pilot/`、台帳は `run_ledger_pilot.csv`（スモークと本実験を汚さない）

3反復とした根拠は、分散の点推定に最低限必要な自由度を確保しつつ、
本実験の費用を圧迫しないため。パイロット自体の結果は本実験の分析に含めない。

## 決定3: N の決め方をあらかじめ書いておく

パイロットのばらつきを見てから決め方を選ぶことがないよう、手順を先に固定する。

1. パイロットの各 spec について、対（同一 spec・同一 rep の B と C）の
   コスト差の相対値 `d = (C - B) / B` を求める。
2. 全 spec・全 rep の `d` の標準偏差 `s_d` を求める（spec をまたいでプールする）。
3. 対応のある検定・両側 α=0.05・検出力 0.80・検出したい効果 δ=0.20 として
   `N = (1.96 + 0.84)^2 * s_d^2 / 0.20^2` を計算し、**切り上げる**。
4. 下限 N=5、上限 N=20 とする。上限に達した場合は本実験を実施せず、
   「事前登録した検出力を現実的な費用で達成できない」ことを結果として報告する。

上限を設ける理由: 2026-08-02 のスモークで、**同一タスクを同一初期状態から
新規セッションで走らせても cost が 17.3% ばらついた**。これは検出したい効果
20% とほぼ同じ桁であり、必要 N が発散しうる。費用が青天井にならないよう、
撤退条件を先に決めておく。
