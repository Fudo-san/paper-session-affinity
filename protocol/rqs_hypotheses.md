## 2. 指標定義（§6.4 の確定リストから役割を指定）

| 役割 | 指標 | 定義 |
|---|---|---|
| **主要評価（RQ1）** | 仕様×反復あたり総費用 USD | ベンダー報告値（input / output / cache_read / cache_write を各単価で加重） |

## 3. 仮説と判定規則

### H1（RQ1・費用）

- **予測**: C の費用は B より低い。削減幅は再探索コスト e の総和に近い（§3.5 P3）。
- **判定**: 対応付き置換検定（spec×rep 対、10,000再標本、両側 α=0.05）で有意、
  かつ BCa 95%CI が 0 を跨がない。
- **「実質的削減」の事前基準**: 中央値ベースで **≥20%** 削減。
  20% 未満の有意差は「削減は実在するが小さい」とそのまま報告する。

### H2（RQ2・時間の非劣性）

- **予測**: レーン継続の直列化による遅延は限定的。
- **判定**: median(T_C) ≤ median(T_B) × (1 + **δ_time**)。δ_time は
  `non_inferiority.md` で凍結【確定 0.15】。bootstrap BCa 片側CI で判定。

### H3（RQ3・品質の非劣性）

- **予測**: セッション継続は品質を実質劣化させない。
- **判定**: 通過率差（C−B）の片側90%CI 下限 > −**δ_q**。δ_q は
  `non_inferiority.md` で凍結【確定 10pp】。検出力不足の場合の扱いは同ファイル §3。

### H4（RQ4・コストモデルの検証）

事前登録する2チェック:

- **(a) 機構レベル**（S2プローブで判定）: warm 境界の初回呼び出しで
  cache_read ≈ H（反復の中央値が **±10%** 以内）。cold 境界（真のTTL超過）で
  cache_creation ≈ H（同 ±10%）。モデル切替で書き直し発生の再現。
- **(b) 端到端レベル**（本実験で判定）: 仕様ごとの費用比 r = Cost_C / Cost_B の実測が、
  §3 モデルによる予測 r̂ に対し **相対誤差 ±25% 以内**が仕様の**過半数**で成立し、
  かつ優劣の符号（C<B か否か）の予測が**全仕様で一致**する。
- 反証時の縮退先: (a) 不成立 → 【A3】棄却 → 主張を session-affinity-aware へ縮退
  （§3.7。研究は成立し続ける）。(b) 不成立 → モデルの適用限界として §8 に記載。

## 4. 検定ファミリーと主張の決定規則

- 構造: **主要評価は RQ1 の1本**。RQ2・RQ3 は主張成立の**共同ゲート**（gatekeeping 構造の
  ため多重比較補正は行わない。この設計自体を §6.5 に記載する）。
- 中心主張「レーン継続は品質・時間を実質犠牲にせず費用を≥20%削減する」を掲げられるのは
  **RQ1有意 ∧ ≥20% ∧ RQ2成立 ∧ RQ3成立** のときのみ。
- 部分成立はそのまま部分成立として報告する。**スピンしない。**

## 5. 実験単位と対応付け

- 単位: spec × arm × rep。B と C は同一 spec・同一反復番号で対にする。
- 実行: アームは時間帯交互配置（ABBA）、仕様内の実行順はランダム化（§6.5）。
- モデル・CLIバージョンは固定し毎ラン記録（`exclusion_rules.md` §4）。

## 6. パイロットの権限（唯一の未凍結項目）

パイロット（1仕様×2アーム×2反復）が決めてよいのは:

1. **反復数 N**（費用の分散から、RQ1 の検出力 0.8 を目標に算定）
2. ハーネスの不具合修正（計装・実行系。判定規則には触れない）

これ以外（仮説・マージン・除外規則・指標定義）は変更しない。

### A-1（2026-08-04）: 仕様 `ct_library`（Contended 形状）を追加

- **変更内容**: §5 の実験単位に spec `ct_library` を加える。**6仕様 → 7仕様**。
  判定規則・指標定義・マージン・除外規則は**一切変更しない**。
- **理由**: 既存3形状では**レーン方式の代償（過剰直列化）が構造的にゼロ**になることが
  判明した。W は 1レーン1タスクで resume が起きず、N は依存関係で既に直列であるため、
  レーン制約が追加の拘束にならない。この構成のままでは「依存で既に直列なタスクの
  セッションを使い回すと安いか」しか問えず、提案手法の代償を一度も測らずに終わる。
  Contended（**依存は無いが write-scope が交差する**）でのみ、
  「並列度を捨てて文脈を再利用する」交換が観測できる。
  設計と検証: `benchmarks/CONTENDED_DESIGN.md`、レーン構成は `build_specs.py` が機械確認
  （1レーン×3タスク）。受入テストは square-media `6f5b695` に実装なしで固定済み。
- **本実験開始前**の追記である（S6 未実施）。
- **規模への影響**: 168ラン → 196ラン（7仕様 × 2アーム × 14反復）。

### A-2（2026-08-24）: アーム C′（予算付きレーン）を**採用しない**

- **変更内容**: 検討していた第3アーム C′ を park する。**本稿のアームは B と C のみ**
  （§1 のスコープを維持）。
- **理由**: CT 単独パイロット（`runs/CT_PILOT_2026-08-24.md`、n=1）で H の実測値が得られた。
  レーン内の H 軌跡は 42.5k → 54.2k → 61.0k で、**resume した2回とも損**

  C′（H < H\* の間だけ継続）は**最初の境界で分割し C′ ≡ B へ縮退**する。
  独立したアームとして情報を持たないため、実験費用（+50%）に見合わない。
- **注記**: `GAPS_2026-08-04.md` §E3 は逆方向（H が H\* に届かず C′ ≡ C）を懸念していた。
  実測は逆だったが、結論（独立した情報を持たない）は同じである。
