# v0.3 追加分析計画（2026-09-05、事後）

ユーザーがv0.2の結果を読んだ後に提案した分析。既存の主判定・マージン・固定予測は変更しない。v0.2一式をpaper/versions/v0.2へ保存済み。

1. 構造的陰性対照W2仕様の相対差・USD差・Cが安い数・相対差中央値BCa95%区間を固定の10000反復/種20260802で示す。プールした28対も同定義。2つの中央値の範囲は記述的参照であり、ノイズの上限・信頼区間・他仕様への閾値ではない。各仕様の生の分布を隠さない。
2. 全98対、非CT84対、W28対、継続対象70対の符号数と二側正確符号検定（同値は除く）を算出する。平均・中央値を区別し、CT/非CTの相対差の和による平均の加法分解を示す。中央値を大きさ寄与に分解しない。
3. 全7仕様のH4bは保持し、Wを除く5仕様の誤差・方向を補助集計する。同一モデルを共有する5仕様の符号を独立公平な試行と仮定して有意性を主張しない。
4. run.jsonの費用とトークンを主集計範囲とする。calls.jsonlは追記履歴なので全行を無条件に合計せず、実行器の記録方法とrun.jsonに一致する最終実行の記録を照合する。CTは全callがrun集計と合うことを確認してタスク別にも示す。
5. 料金項目別の会計的分解は入力・出力・cache read・cache writeを既存較正の固定単価で換算し、報告費用との差を残差として必ず保持する。トークン集計だけでモデル別請求内訳を復元できない場合は無理に一致させない。価格を実測総額にフィットして再較正しない。中央値+50.6%の加法分解と総額差の加法分解を混同しない。
6. CTの報告ターン総数と記録されたturn行数の差を照合する。ターン詳細が部分的ならその範囲でのみ分析する。cache readを継承履歴だけに帰属させる情報がなければ、固定文脈・現タスク履歴との混在を明記し、carry式の各項の直接同定を主張しない。
7. 主な数値はJSONから本文表・図へ生成。合成データで費用分解の加法一致、符号検定、平均/中央値の相違、再実行ログの選別を確認する。実データでは照合と記述のみ。新しいAPIランは実施しない。
