ただし「測定系のノイズ幅を確立」「CTだけがノイズを超える効果」は採用しない。Wの全観測は−43.4%〜+26.7%、CTの最小は+24.2%で一部重なる。2つの中央値はノイズ分布の上限や有意性閾値ではない。
W28対をプールした中央値−4.44%、BCa95%区間[−11.52%,+10.12%]、Cが安い15/28を併記。仕様ごとの区間とUSD差も示し、費用規模・課題固有性・各14対という制約を明示した。対照値の差し引き補正はしていない。

## 2. 44/98とp=0.0013 — 採用、中央値と平均を区別

全98対: Cが安い44、高い54、同値0。二側正確符号検定p=0.3634。
非CT84対: Cが安い44、高い40。52.4%、符号検定p=0.7436。
平均相対差+8.37%の加法的寄与はCT+7.12ポイント、非CT+1.25ポイント。
平均ベースの符号反転検定p=0.0013は差の大きさを使い、符号検定は頻度を使う。
一方、「中央値の正符号が多数決ではなく少数の大きな増加で生じる」は採用しない。全体では実際に正の差が多数であり、中央値の符号は順位に依存する。CT14件を足すと正の差が40→54となることを示した。

## 4. 料金項目・タスク別分解 — 実施、新しい制約と所見を確認

CT全28ランのrun.jsonと各3呼び出しの5集計項目が一致した。全体の他仕様では追記履歴があるため、無条件にcalls.jsonlを合計しない。

| CTの14ラン合計 | B | C | 増減 |
|---|---:|---:|---:|
| 報告費用 USD | 9.5434 | 14.2279 | +4.6845 |
| 報告ターン数 | 587 | 572 | −2.6% |
| cache read | 19,743,378 | 26,177,435 | +32.6% |
| cache write | 948,096 | 1,865,384 | +96.8% |

既存較正の固定単価で換算すると増分+5.4529 USDのうちwrite+3.4398（63.1%）、read+1.9302（35.4%）、output+0.0829、input−0.000018。
CLI報告額との差の変化−0.7684 USDを残差として併記した。従って63.1%等は固定単価換算の構成比であり、実際の請求増分の内訳ではない。
ログは代表モデルに加え補助モデルの使用を記録するが、modelUsageのモデル別金額・トークン数は保存していない。価格を総額に合わせてフィットしない。
ターン詳細551/530行はCLI報告数587/572と一致せず、Bの入力項目にも差がある。partial outputは未確定値なので利用しない。

さらに新規で始まるCT-Aにも+1.3808 USD（CT総増加の29.5%）があり、ターン数238→316。継続する後続2タスクは349→256。
このため全増加を継承履歴の直接費用にはできない。read/writeのトークンに継承履歴・固定文脈・現タスク内履歴の出自はなく、carry式の各項を独立に埋めるだけの観測はない。
料金項目の増減は示せたが、請求の完全分解や継承履歴の因果寄与の同定には至っていない。
