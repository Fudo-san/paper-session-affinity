# §8 Threats to Validity / Limitations（ドラフト v0.1）

> 状態: S6 完走直後に、運用の経緯が失われないうちに書く。
> 隠さない。事前登録（`protocol/`, FROZEN）と Amendment Log に記録した事実を
> そのまま並べる。数値の出所は `analysis/e2_results_main.json`（commit `f54c229`）。

## 8.1 中心的洞察の一部が実測で否定された

本研究は当初「**TTL は与えられた制約ではなく、スケジューリング可能な資源である**」を
中心的洞察とした（§3.5）。境界ギャップ g をスケジューラが制御できるため、
後続タスクを TTL 内に投入すれば境界を warm に保てる、という主張である。

**M7（2026-08-04、12測定）でこの主張の一部が否定された。**

初回 resume の書き直し（指示変数 ρ）は損益分岐点をおよそ半分にする
（H\*₁ ≈ 0.5·E）が、その発火条件は**プロンプトのサイズではなかった**。

| 追加量（文字） | 500 | 1,000 | 2,000 | 4,000 | 8,000 | 16,000 |
|---|---|---|---|---|---|---|
| ρ | **1** | 0 | 0 | 0 | 0 | 0 |

16,000文字で発生せず500文字で発生する以上、サイズ仮説は成立しない。
実際に効いていたのは **init 時点の CLI 側キャッシュ状態**であり
（init の cache_read で完全分離）、**クライアントからは制御できない**。

したがって、クライアント側スケジューリングで動かせる範囲は当初の想定より狭い。
g は制御できるが、損益を同程度に左右する ρ は制御できない。
これは本研究の限界であると同時に、**変更不能な商用API上でクライアント側から
何ができて何ができないかを画定した所見**でもある。

なお ρ は**事後には観測できる**（init の cache_read で分離）。観測後に適応する
スケジューラは拡張候補だが、本稿のスコープ（アームD は park）を超えるため扱わない。

## 8.2 単一仕様が結果の符号を決めている

RQ1 の全体中央値 +5.5% は、**7仕様のうち `ct_library` 1件が支配している**。

| spec | 相対差 中央値 | C が安い対 |
|---|---:|---:|
| `ct_library`（CT） | **+50.6%** | **0/14** |
| 他6仕様 | −7.9% 〜 +12.1% | 5〜10/14 |

CT を除けば効果はほぼ拮抗する（98対中44対で C が安い）。
CT は**依存が無いのに write-scope が交差する**唯一の形状であり、
レーン方式の代償（過剰直列化）が測れる唯一の仕様である。

この構成は Amendment A-1（2026-08-08）で追加した。既存3形状（W/N/M）では
代償が構造的にゼロになることが判明したためである。**CT を追加していなければ
本実験は代償を一度も測らずに終わっていた。**

### 感度分析（副次。主要判定には使わない）

`exclusion_rules` §5 は極端値を除いた感度分析を**副次としてのみ**許可している。
以下は参考値であり、判定は §6 の全98対によるものが正である。

| 対象 | n | 相対差 中央値 | p 値 | BCa95%CI(USD) |
|---|---:|---:|---:|---|
| **全98対（主要判定）** | 98 | **+5.5%** | 0.0047 | [−0.0173, +0.0581] |
| (a) 離隔層11対を除外 | 87 | +6.0% | 0.0112 | [−0.0189, +0.0581] |
| **(b) `ct_library` を除外** | 84 | **−1.4%** | **0.9045** | [−0.0270, +0.0312] |
| (a)+(b) 両方を除外 | 75 | −1.1% | 0.9177 | [−0.0259, +0.0312] |

**`ct_library` を除くと効果が消える。** 中央値は −1.4%（符号反転）、p=0.90 で
まったく有意でなく、C が安い対は 44/84（52%）とちょうど半々になる。

一方、離隔層11対の除外は結果をほとんど動かさない（+5.5% → +6.0%）。
**§8.3 の層の非均質性は、結論に影響していない。**

つまり本実験が検出したのは「レーン継続が一般に費用を増やす」ことではなく、
**「CT 型（依存が無いのに write-scope が交差する）の競合が存在する場合に、
レーン継続が過剰直列化の代償を払う」**ことである。
それ以外の形状では、費用は増えも減もしない。

一方で、**7仕様中1仕様が符号を決める構成は外的妥当性を弱める**。
実運用のタスク分布において CT 型の競合がどの程度の割合を占めるかは本研究では測っていない。
結果は「CT 型の競合が存在するワークロードでは、レーン継続は費用を増やす」
と読むべきであり、任意のワークロードへ一般化できない。

## 8.3 対内の実行間隔が層で異なる（Amendment A-5）

実行順を途中で変更した。当初はアーム主体（1反復内で全仕様の第1アーム → 第2アーム）
だったが、利用上限が来ると**必ず対が割れる**ことが実測されたため、
仕様主体（B→C を隣接）へ戻した。

対内の B/C 間隔を実測すると、層がきれいに分かれる。

| 層 | 対数 | 間隔の中央値 | 範囲 |
|---|---:|---:|---|
| rep1〜2（アーム主体） | **11** | 28〜30 分 | 19.7 〜 38.2 分 |
| rep3〜14（仕様主体） | **87** | **0.0 分** | 0.0 〜 0.4 分 |

対応付けは (spec, rep) 単位で閉じており、各対は自身の条件内で B と C を比較している。
したがってこれは**対内の交絡ではない**。しかし対によって「B と C がどれだけ離れた
時点で実行されたか」が異なり、11対は最大38分離れている。

A5 汚染（resume が作ったキャッシュを後続の fresh が踏む）は run ごとの nonce で
遮断してあり、間隔に依存しない。それでも、時間帯・サービス側の負荷変動が
11対にだけ余分に乗る可能性は残る。**該当11対を除いた感度分析を副次として報告すべきである**
（`exclusion_rules` §5 は極端値を除く感度分析を副次に限って許可している）。

## 8.4 停止条件が発火した（Amendment A-6）

E1 は `exclusion_rules` §3 の停止条件（インフラ起因の再実行率 20% 超）に該当し、
判定を拒否した。E1 の算出値は **61.7%**（インフラ起因121件 / run 196本）。

分子の解釈にずれがあった。E1 は**中断イベントの延べ回数**を数えていたが、
§3 が意図するのは**やり直しが発生した run の本数**である。
121件のうち上位8本の run（各10〜13回中断）だけで **94件**を占めていた。

正しい指標では **27 / 196 = 13.8%** であり停止閾値の内側になる。
また中断はアームB 66件（54.5%）／アームC 55件（45.5%）でほぼ均等であり、
系統的なバイアスを持ち込む形にはなっていない。

**この判断はデータを見る前に行い、Amendment A-6 として記録してから E2 を実行した**
（commit の順序が証拠になる）。E1 の閾値判定ロジックは変更していない。
判定を通すには `--acknowledge-stop A-6` の明示が要り、判定結果に Amendment ID が刻まれる。

それでも、**実行環境が不安定だった事実は残る**。原因は
(1) 一過性 429 に対するフレームワークの60分ローカル遮断とその誤検知、
(2) アーム主体の実行順、(3) `git worktree` の不整合、(4) 実際の利用上限、
の4つで、(1)〜(3) は実験中に修正した。修正が結果へ与えた影響は評価していない。

## 8.5 コストモデルは C の不利を系統的に過大評価する

H4b は大きさの条件（±25% 以内が過半数）を 6/7 で満たしたが、符号一致で不成立となった。

**誤差の向きが揃っている点が重要である。7仕様すべてで実測 < 予測**
（−37.2% 〜 +3.3%、うち6仕様が負）。偶然の散らばりであれば正負が混ざるはずで、
これはモデルに構造的な偏りがあることを示す。

`§3.7` の縮退先に従い、これはモデルの適用限界として扱う。原因の候補は
E と W の分離定義（§8.6）、較正データの薄さ（§8.7）、ρ の扱いだが、
本研究では**判別していない**。

## 8.6 E と W の境界は操作的定義であり恣意的

コストモデルは再探索コスト E と本来の作業 W を分けるが、
両者はタスク単位の合計 usage からは識別できない（【A2】訂正記録）。
`--output-format stream-json` により per-turn の usage が得られるため、
**「最初に編集系ツール（Write/Edit）を呼ぶまでのターン群を E、以降を W」**
という操作的定義を置いた（§3.8.3）。

この境界に原理的な根拠はない。エージェントが編集の合間に再探索することもあり、
その分は W に算入されている。境界を1ターンずらした場合の感度分析を
副次として報告すべきだが、本稿では実施していない。

## 8.7 較正データが薄い

H4b の予測 r̂ は、独立した較正キャンペーン（`runs/calib`、**アームB のみ**・
7仕様 × **1反復**・$5.88）から機械計算した（Amendment A-3）。
`§3.8.4` の独立性要件（パイロットの C/B 比を使わない）は満たしているが、
**1反復では E と H の分散を評価できない**。

r̂ の系統的な過大評価（§8.5）が較正の薄さに由来する可能性は否定できない。

## 8.8 品質の非劣性は検出力が低い

H3 は非劣性成立と判定されたが、**受入全通過率は二値・98対**である。
C 側で落ちたのは1件のみ（B 100% / C 99.0%）で、
CI90 下限が +0.00pp と「低下の証拠が無い」ことは言えるが、
`non_inferiority.md` §3 が想定するとおり**検出力は高くない**。

「品質低下の証拠はない」と「品質が劣化しないことを確立した」は異なる。
本研究が言えるのは前者である。

## 8.9 執筆者の非盲検（開示）

本研究は単一の執筆者が設計・実行・分析・執筆をすべて担った。
以下を開示する。

- **パイロットの向き（7仕様中5仕様で C が高い、平均 +12.7%）を見た後に**
  アーム C′（予算付きレーン）を発想した。C′ は最終的に CT パイロットの実測に基づき
  park したが（Amendment A-2）、着想が観測後である事実は残る。
- 同じ理由から、`§3.8.4` は r̂ を**手入力せずコミット済みスクリプトで機械計算する**
  ことを義務づけた。無意識の適合を式の表現力内に閉じ込めるための措置であり、
  完全な盲検ではない。
- A-6（停止条件からの再開）は B/C の比較値を見る前に判断・記録した。

## 8.10 再現の非対称性 — レベル2は第三者が再実行できない

本研究の再現可能性は**分析側と実験側で非対称**である。

| | 範囲 | 第三者による再実行 |
|---|---|---|
| レベル1 | 196ランの生データからの集計・判定・図表 | **可能**。同梱データで完結する |
| レベル2 | 196ランそのものの再実行 | **不可能**。装置が公開されていない |

実験を回したハーネス（MAS フレームワーク）と、実験された対象リポジトリの
いずれもライセンスが設定されておらず、**本研究では再配布しないと決めた**
（`THIRD_PARTY_NOTICES.md` §3）。したがって公開物に含まれるのは
実験手順と仕様の**記述**であって、装置そのものではない。

**帰結**: 本研究の数値は、第三者が独立に再取得して検証することができない。
検証できるのは「同梱データから同じ結論が出るか」までである。
§4 の決定規則を機械適用した点と事前登録の凍結（`protocol/` FROZEN v1.0）は
この弱点を部分的にしか補わない。事前登録は**分析者の自由度**を封じるものであり、
**データ生成そのものの独立検証**の代わりにはならない。

これは本研究に固有の欠陥ではなく、変更不能な商用APIを私有リポジトリ上で測る
実験設計に共通する制約である。ただし共通であることは弱点を消さないので、
**主張の強さはこの範囲に留める**。

  **他モデル・他バージョンへの一般化は保証しない**。
