# 分析前確定事項 — 2026-08-02

## この文書の役割

`protocol/` の3文書は FROZEN であり、**本文書はそれらを変更しない**。
凍結文書に**書かれていない実装上の曖昧点**を、本実験のデータが1件も存在しない
時点で確定させる。後から決めると、分析方法を結果に合わせて選べてしまう。

確定時点で存在するデータは、パイロット（`runs/pilot2/`、N の決定にのみ使用）
までである。以下の決定はいずれもパイロットの検定結果を見ずに行った
（E2 はパイロットに対して実行していない）。

## 決定A: 対の差は「相対差」で扱う

`rqs_hypotheses.md` §3 H1 は有意性を「対応付き置換検定」、実質性を
「中央値ベースで ≥20% 削減」と定めるが、**検定にかける量が絶対差か相対差かを
書いていない**。

**相対差 d_i = (Cost_C − Cost_B) / Cost_B を主要な量とする。**

理由:

- 仕様間で絶対費用が 0.49〜1.71 USD と3倍以上ちがう。絶対差で検定すると
  高価な仕様が結果を支配し、仕様をまたいだプールの意味が薄れる。
- 実質性の基準（≥20%）が相対値で定義されているため、同じ尺度で統一する方が
  整合する。

絶対差による検定結果も**副次として併記**する。主要判定には使わない。

## 決定B: 有意性は平均、実質性は中央値（役割で使い分ける）

`rqs_hypotheses.md` は「対応付き置換検定」とだけ書き、統計量を指定していない。
一方で実質性の基準は「中央値ベースで ≥20%」と中央値を名指ししている。

- **有意性（置換検定の統計量）: 平均 mean(d_i)**
- **実質性（≥20% の判定）: 中央値 median(d_i)**（凍結文書の指定どおり）

中央値による置換検定も**副次として併記**する。

### 平均を検定統計量にする理由

当初は「実質性が中央値なら検定も中央値で揃える方が一貫する」と考えたが、
合成データによる検証で**中央値は符号反転検定の統計量として機能しない**ことが
判明した（`tests/test_stats.py::test_median_is_a_poor_permutation_statistic`）。

差が全て同じ大きさ 1.0 の20対を考える。符号を反転すると、正が11個以上なら
中央値は +1、9個以下なら −1 になる。つまり **82% の確率で観測値と同じ大きさ**に
なり、p 値が 0.82 まで上がる。中央値は差の**大きさ**を無視するためである。

実データは値がばらけるのでここまで極端にはならないが、大きさを捨てる性質は
同じで、検出力が落ちる。符号反転検定の標準的かつ最も検出力の高い統計量は
平均（あるいは和）である。

### 一貫性を欠かないか

欠かない。凍結文書 §3 H1 は
「20% 未満の有意差は『削減は実在するが小さい』とそのまま報告する」と定めており、
**有意性と実質性が別々の判断であることを最初から想定している**。
それぞれを、凍結文書がその役割に対して指定した統計量で判断する。

この決定は本実験のデータを見る前に、合成データの挙動だけを根拠に行った。

## 決定C: 置換の帰無仮説は符号交換可能性

対応付きデザインの標準に従い、**各対の差の符号をランダムに反転**して
帰無分布を作る。再標本数は凍結文書どおり 10,000。

p 値は `(超えた回数 + 1) / (再標本数 + 1)` とする（Phipson & Smyth 補正）。
p が 0 になることを避けるため。したがって最小 p は 1/10001。

## 決定D: 乱数種を固定する

置換検定・ブートストラップの種は **20260802** に固定し、スクリプトに直書きする。
再現性のため。種を変えて結果を見比べることはしない。

## 決定E: H4(b) の予測値は本実験前に確定させる

`rqs_hypotheses.md` §3 H4(b) は「§3 モデルによる予測 r̂」との比較を求めるが、
**r̂ の具体値がまだ無い**。

本実験を開始する前に、仕様ごとの r̂ を `analysis/model_predictions.json` へ
書き込み、コミットする。**予測が存在しない状態で本実験を回してはならない。**
実測を見てから予測を作れば、H4(b) は検証ではなく後付けになる。

E2 は `model_predictions.json` が無い場合、H4(b) を「予測未登録のため判定不能」
として明示的に報告する。黙って飛ばさない。

## 決定F: 欠測対の扱い

`exclusion_rules.md` §3 は、インフラ起因の再実行が2回目に失敗した spec×rep を
「欠測として記録し、補充しない」と定める。

欠測対は**対応付きの解析から除外**する（対が成立しないため）。
除外した対の一覧と件数を Results に必ず明記する。欠測率も報告する。

## 決定G: 層（stratum）の分離

`exclusion_rules.md` §4 は、モデルIDまたはCLIバージョンがドリフトした場合に
別層として分離報告するか再実行するかを求める。

E1 は全 run のモデルIDとCLIバージョンを集計し、**2種類以上あれば警告して停止**する。
混ぜて集計することはしない。分離するか再実行するかの判断は人間に返す。
